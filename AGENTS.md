# TohaVibeCode

Локальный помощник учителя: веб-приложение на aiohttp, которое разбирает методички
PDF, генерирует по ним сообщения через OpenAI-совместимый ИИ и рассылает результат
в беседы ВК (или кладёт в буфер обмена).

## Commands
- Запуск: `python app.py` — сам поднимает сервер из `[server]` и открывает браузер.
- Зависимости: `pip install -r requirements.txt`.
- Линт: `python -m ruff check .` (конфига нет, ruff берёт дефолты).
- Синтаксис фронта: `node --check web\app.js`.
- Ручная проверка токена: `python test_vk_token.py [--send PEER_ID]`.
- Тестового фреймворка в проекте нет — см. Tests.

## Architecture
- `app.py` — единственная точка входа. aiohttp-роуты, `Context` в `app["ctx"]`,
  вся сборка ответов JSON. Не ходит в VK и ИИ сам, только зовёт `core/` и `sender/`.
- `core/` — логика без знания о вебе: `config.py` (pydantic-модели),
  `config_store.py` (запись TOML), `pdf_parser.py`, `prompt_builder.py`,
  `llm.py`, `vk_api.py`, `history.py`, `thumbs.py`, `naming.py`.
- `sender/` — единственное место, где живёт VK-токен при отправке: `VKSender`,
  `ClipboardSender`, сборка `Sender` через `build_sender` (`sender/__init__.py:31`).
- `web/` — ванильный JS без сборки. Состояние в `state`, API через `api()/post()`.
  Оформление разделено на `theme.css` (токены, светлая/тёмная тема, база) и
  `style.css` (компоненты поверх токенов). Цвета в `style.css` — только через
  переменные из `theme.css`; новую тему проверять в обеих.
- Настройки живут в `config.toml`, но правятся из веба: `POST /api/settings`
  → `core/config_store.save_config` → `Context.apply` (`app.py:76`) пересоздаёт
  клиента и отправителя, перезапуск не нужен.

## Conventions
- Тексты ошибок и подсказок — по-русски, внятно; технические детали (код ВК,
  имя файла) добавляются в конце.
- Любая работа с файлами и `pypdf` — через `asyncio.to_thread` (`app.py:127`).
- Путь к файлу из запроса собирать только через `Context.lesson/photo/history` —
  это `_resolve()` с `Path(name).name`, единственная защита от `..`
  (`app.py:82`). Собирать `dir / request.query[...]` руками нельзя.
- Адреса ИИ-провайдеров живут только в `LLM_PROVIDERS` (`core/config.py:12`);
  `base_url` в UI — лишь подстановка пресета.
- `config_store.render_config` пишет TOML сам и проверяет round-trip через
  `AppConfig.model_validate(tomllib.loads(text))`. Добавляя поле в
  `core/config.py`, допиши его и в `render_config`, иначе настройка не переживёт
  сохранение.
- Новый роут — в список `app.router.add_routes` (`app.py:662`), возвращать
  `_json(...)`, исключения ловит middleware `errors` (`app.py:133`).
- Фронт адресует DOM **только по id** через `$()`. Переименовал id в
  `index.html` — поправь `$("…")` в `web/app.js`, иначе страница сломается молча.
- Ассеты лежат плоско в `web/`: `/assets/{name}` не заходит в подкаталоги.
  Шрифты и иконки — свои, из инлайн-SVG-спрайта в `index.html` (`<symbol id="i-…">`),
  без CDN.
- Тема ставится до первой отрисовки инлайн-скриптом в `<head>` из
  `localStorage["tohavibe.theme"]`; ключ продублирован в `web/app.js` как
  `THEME_KEY`. Менять — в обоих местах.
- Иконка-кнопка: `<button class="icon" title="…"><svg><use href="#i-…"></use></svg></button>`
  плюс `.visually-hidden` с текстом, иначе кнопка без имени для скринридера.
- Класс `.is-busy` на кнопке прячет содержимое через `visibility` — нельзя
  подменять `textContent`, иначе пропадёт иконка.
- Кнопочная активность — только через `guard(button, action, statusId)`
  (`web/app.js`): он сам снимает блокировку в `finally` и зовёт `syncActions()`.
- Иконки из JS рисуются только через `svgEl()` (`createElementNS`): обычный
  `createElement("svg")` даёт элемент в HTML-пространстве имён, и `<use>` на
  символ спрайта не резолвится — иконка выходит пустым квадратом.
- Строки методичек и бесед кликабельны целиком (`li.pickable`, чекбокс ставится
  кликом по строке), отмеченные подсвечиваются `li.picked`. Клик по кнопке внутри
  строки обработчик строки игнорирует.
- Методичка открывается в системном просмотрщике через `POST /api/lesson/open`
  (`app.py`, обработчик `open_lesson`, `_open_file`): путь собирается только через
  `ctx.lesson`, `os.startfile` под Windows, `xdg-open`/`open` на прочих системах.
- Подтверждения — своим `confirmDialog()` (`#dlg-confirm`), системный `confirm()`
  в проекте больше не используется.
- Черновик пишется в `localStorage["tohavibe.draft.v1"]` (`DRAFT_KEY`) и чистится
  после успешной отправки и сохранения.
- Доступность провайдера ИИ проверяет сервер: `probe_llm`/`_require_llm` в
  `app.py`, кэш на `LLM_HEALTH_TTL`, статус лежит в `state.llm.health`, клиент
  берёт его в `renderLlmHealth` и гасит кнопки в `syncActions()`. Новый роут
  генерации обязан звать `_require_llm(ctx)` первым делом.
- Список моделей — `core/llm.list_model_details`, у локального адреса берётся из
  нативного `/api/v0/models` (LM Studio) с пометкой `state`. Новые источники
  моделей дописываются туда, в UI — только рендеринг `renderModelOptions`.
- Длинные списки (методички, фото) режутся постранично: `LESSON_PAGE`,
  `PHOTO_PAGE`, общий `renderPager()`. Пагинация должна быть **вне**
  `.list-scroll`, иначе она уезжает при прокрутке; сам `.list-scroll` —
  единственный прокручиваемый элемент панели.
- На широком экране страница не прокручивается: `html, body { height: 100%;
  overflow: hidden }` в медиа `min-width: 901px`, колонки заданы в `100vh`.
  Без `contain: paint` на `.list-scroll` содержимое списка всё равно растягивало
  документ (`documentElement.scrollHeight` 1980 при окне 900) и страница
  прокручивалась в пустоту — проверено колесом мыши в headless Edge.
- Панель-источник (`#panel-lessons`, `#panel-photos`) не должна быть
  скролл-контейнером: `overflow` у неё остаётся `visible`, прокручивается
  только `.list-scroll`. Иначе любой 1px перелив (например, `transform` у
  нажатой кнопки) даёт у панели скроллбар на 15px, который отжимает список.
  Поэтому у `button:active` только `opacity`, без сдвига, а класс
  `scroll-pane` в разметке не используется.

## Tests
- Фреймворка нет. Проверки пишутся как одноразовые скрипты в
  `%TEMP%\opencode` (вне репозитория), гоняются через `aiohttp.test_utils`
  `TestServer` на реальном `create_app()` и удаляются после прогона.
- Проверять надо в первую очередь: отказ вместо 500 на кривых данных,
  сохранение `config.toml` (sha256 до/после), и что `_resolve` не пускает `..`.
- После правок фронта обязателен скрипт-сверка: id из `$("…")` в `web/app.js`
  против `id="…"` в `web/index.html`, `<use href="#i-…">` против `<symbol id="i-…">`,
  поиск系统ного `confirm(`, и 200 на `/`, `/assets/*.css`, `/assets/app.js`.
  Проверку надо уметь уронить: временно переименуй id и убедись, что скрипт
  упал, — иначе он ничего не проверяет.
- Ловушки: порядок истории при равных mtime недетерминирован (нужен `os.utime`);
  в PowerShell без `$env:PYTHONIOENCODING="utf-8"` ломается кириллица;
  битое фото `/api/photo/thumb` отдаёт оригинал, а не ошибку.

## Forbidden
- Не читать, не печатать и не коммитить токены (`[vk]` в `config.toml`) —
  только программно через `load_config()`.
- `config.toml.bak` — автобэкап с секретами, руками не трогать и в репозиторий
  не тащить.
- `photos/.thumbs/` — кэш миниатюр, генерируется сам, удаляется вместе с фото.
- `.ruff_cache/`, `__pycache__/`, `photos/`, `history/` — не в репозиторий.

## Context
- Лимит в 10 фото живёт только в `sender/vk_api.py:28` (`MAX_ATTACHMENTS`) и
  применяется молча, срезом `photos[:MAX_ATTACHMENTS]`. Фронт держит свой счётчик
  и блокирует 11-е фото сам; в режиме буфера обмена лимита нет вовсе.
- `peer_id` мультичата индивидуален для каждого участника: у человека один,
  у сообщества другой. Поэтому ID беседы из ссылки пользователя не подходит
  боту, и беседы приходится находить перебором `peer_id`
  (`core/vk_api.py`, `scan_chats`) и мержить с `messages.getConversations`.
- `messages.getConversationsById` нельзя батчить: один недоступный `peer_id`
  роняет всю пачку (927).
- Отправка фото требует у community-ключа галочки «доступ к фотографиям»;
  без неё `photos.getMessagesUploadServer` даёт код 15, и это не лечится кодом.
